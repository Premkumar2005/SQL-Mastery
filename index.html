Pattern: Read rows, apply conditions, use NULL handling
0/0

Pattern: COUNT, SUM, AVG, MIN, MAX + HAVING to filter groups
0/0

Stage 4 — JOINs
Pattern: INNER, LEFT, SELF JOIN — combining multiple tables
0/0
Pattern: LEFT JOIN keeps all rows from left table (NULL where no match — great for "not in" logic). INNER JOIN keeps only matches. SELF JOIN joins a table to itself (e.g. manager-employee). Master this stage — it's 60% of interviews.

Stage 5 — CASE WHEN & Conditional Logic
Pattern: IF/ELSE inside SQL — pivoting, categorizing, conditional counts
0/0
Pattern: CASE WHEN condition THEN val ELSE val END. Use inside SELECT, SUM, COUNT. Conditional aggregation: SUM(CASE WHEN status='approved' THEN 1 ELSE 0 END) counts approved rows. Pivoting = rotating rows to columns using CASE.

Stage 6 — Subqueries & CTEs
Pattern: Nested queries, EXISTS/IN, WITH clause for readability
0/0
Pattern: Subquery in WHERE: WHERE id NOT IN (SELECT ...). CTE: WITH cte AS (SELECT ...) SELECT * FROM cte. Use CTEs to break complex problems into named steps. Correlated subquery runs once per row — use carefully for "find latest per group" problems.

Stage 7 — Window Functions
Pattern: RANK, ROW_NUMBER, LAG/LEAD, SUM OVER — analytics without collapsing rows
0/0
Pattern: RANK() OVER (PARTITION BY dept ORDER BY salary DESC). Key functions: RANK (gaps), DENSE_RANK (no gaps), ROW_NUMBER (unique), LAG/LEAD (prev/next row), SUM OVER (running total). Wrap in CTE then filter: WHERE rn = 1.

Stage 8 — Date & Time Functions
Pattern: DATEDIFF, DATE_TRUNC, self-join on dates, time series analysis
0/0
Pattern: DATEDIFF(d2, d1) or d2 - d1 for day gaps. DATE_TRUNC('month', date) for monthly grouping. For "next day" comparisons, self-join on date +/- interval or use LAG/LEAD. Know: YEAR(), MONTH(), DAY(), EXTRACT().

Stage 9 — Hard / Mixed Patterns
Combine everything: retention, gaps, purchase patterns, advanced analytics
0/0
Pattern: These require chaining multiple techniques. Approach: (1) identify what each part needs, (2) write CTEs for each part, (3) join them. Retention = users active in month M AND M+1. Gaps = LAG to find prev date, subtract. Pairs = self-join with a < b to avoid duplicates.

Pattern-First Solving Strategy

1
Before coding, identify the pattern: filter? aggregate? join? window? This alone cuts solve time in half.
2
Stage 4 (JOINs) + Stage 7 (Windows) appear in 80% of interviews. Spend 2× more time here.
3
Write CTEs for any query with 2+ logical steps. Readable SQL = fewer interview mistakes.
4
HackerRank problems are great for syntax drilling. DataLemur problems mirror real interview questions best.
5
After solving, look up the editorial. Often there's a smarter pattern you didn't consider.
6
Solve 1 problem daily minimum. Consistency beats marathon sessions — patterns stick through repetition.
